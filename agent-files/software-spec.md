# 校園設備報修系統: 軟體規格書

## 系統目標

1. **提供直覺的校園報修管道**：讓全校師生（學生、教職員）能隨時透過網頁表單即時通報損壞設備，免去繁瑣的紙本或跨處室傳遞流程。
2. **建立透明的維修追蹤機制**：提供公開的案件清單，讓報修者隨時掌握設備目前的維修進度與歷史案件，避免重複通報。
3. **集中化的維修管理後台**：提供校園設備管理人員集中的後台管理介面，便於指派進度、變更維修狀態與清理失效案件。
4. **教學與原型驗證（MVP）**：作為 MIS 資訊管理課程的教學範例，展示前後端資料流、表單驗證、非同步資料更新（SPA 體驗）以及管理員權限鑑權機制之運作。

---

## 使用者

1. **一般使用者（學生、教職員）**
   - **角色定位**：校園設備的使用者與問題通報者。
   - **存取權限**：無需登入即可使用前台所有功能。
   - **主要行為**：填寫並提交設備報修表單、檢視全校公開的報修案件狀態、手動重新整理清單以獲取最新處理情況。

2. **設備管理員（總務／資訊維修人員）**
   - **角色定位**：負責設備維修進度掌控、案件分流與資料維護的管理人員。
   - **存取權限**：必須透過帳號與密碼完成身分驗證方可進入管理後台。
   - **主要行為**：登入與登出系統、檢視所有報修案件詳細資訊、切換並儲存案件處理狀態（待處理／處理中／已完成）、刪除無效或重複通報的案件。

## 核心功能

### 1. 前台報修與進度查詢模組
- **建立設備報修單**
  - 提供表單介面供使用者輸入報修資訊，包含：地點、設備名稱、緊急程度（一般／急件／緊急）、聯絡方式以及故障問題描述。
  - 使用者提交後，系統於前端即時發送資料，無須重新載入整個網頁即可完成報修。
  - 後端接收後自動生成專屬案件編號（例如：T-001、T-002 格式遞增），自動記錄當前建立時間，並將初始狀態設定為「待處理」。
  - 建立成功後，於頁面上呈現即時反饋訊息（包含案件編號），並自動清空表單輸入內容供下次填寫。
- **即時案件清單檢視**
  - 首頁載入時自動取得並呈現所有已登錄的報修案件。
  - 表格清晰展示案件編號、故障地點、設備名稱、緊急程度、聯絡人資訊、當前處理狀態、問題說明與通報時間。
  - 提供「手動重新整理」按鈕，允許使用者在不重整網頁的情況下獲取最新案件資料。
  - 若系統目前無任何案件，介面自動顯示友善的「目前尚無報修案件」提示。

### 2. 管理員身分驗證模組
- **管理員登入**
  - 當訪客嘗試存取受保護的管理後台時，系統自動導向至專屬的身分驗證登入頁面。
  - 提供帳號與密碼輸入欄位；若輸入錯誤，頁面即時反饋錯誤警告訊息，且不放行存取後台。
  - 驗證成功後，系統建立已授權的連線狀態（Session），並自動跳轉至管理後台主頁面。
- **已登入狀態防呆與重定向**
  - 若使用者已成功登入管理員身分，再次進入登入頁面時將自動直接跳轉至後台，無需重複登入。
- **安全登出**
  - 管理後台導覽列提供顯著的登出操作連結。
  - 點擊後立即註銷管理員登入憑證，並導回登入頁面，確保公共設備上的操作安全性。

### 3. 案件管理與處置模組（管理員專屬）
- **後台案件總覽**
  - 提供管理專用資料表格，整合顯示所有報修單之核心資訊、通報時間與完整問題描述。
  - 支援手動重新整理功能，方便即時同步最新提交的案件。
- **維修狀態更新**
  - 後台表格針對每筆案件提供獨立的狀態下拉選單（包含「待處理」、「處理中」、「已完成」）。
  - 管理員變更狀態並點擊「儲存狀態」後，系統即時向後端同步修改，並在成功後提示操作結果並更新清單顯示。
- **案件刪除與防呆機制**
  - 管理員可針對重複、測試或無效之報修單點擊「刪除」按鈕。
  - 為防止誤觸，點擊時觸發二次確認機制（對話確認框），使用者確認同意後方才執行案件移除。
  - 案件移除後即時更新後台列表並提示刪除成功訊息。

## 限制與規則

### 1. 資料完整性與防呆規則
- **必填欄位限制**：地點、設備名稱、聯絡方式、問題描述皆為必填項目，任一欄位為空或純空白時系統將拒絕受理並提示具體缺失欄位。
- **緊急程度預設值**：若使用者未明確選取緊急程度，系統預設採用「一般」。
- **狀態流轉限制**：案件處理狀態嚴格限制為「待處理」、「處理中」、「已完成」三種合法值，不允許填入自訂或未知狀態。

### 2. 存取權限與安全規範（縱深防禦）
- **介面層存取限制**：未經身分驗證之訪客嚴格禁止存取管理後台頁面（`/admin`），系統將自動將其重定向至登入頁面（`/login`）。
- **API 層嚴格授權檢核**：
  - 案件查詢（讀取）與案件建立（提交）為全校公開功能。
  - 案件狀態修改與案件刪除屬於敏感特權操作，後端服務在執行業務邏輯前，必須強制檢查管理員憑證；未登入者一律阻擋並回應未授權拒絕（HTTP 401），防範透過腳本或開發者工具繞過前端畫面的越權攻擊。
- **身分憑證防偽**：使用伺服器端密鑰簽章之安全 Session 機制記錄管理員狀態，防止客戶端自行偽造身分。

### 3. 系統環境與資料生命週期限制
- **記憶體暫存機制（In-Memory Storage）**：目前系統案件儲存於伺服器執行階段之記憶體列表中，伺服器重啟或停止執行後所有案件資料將全數重置清空。
- **單一管理員設定**：目前系統採用單組內建固定管理員帳密（`admin` / `admin`）進行身分比對，適合作為課堂演示使用。

## 完成條件

1. **前台通報流程驗收**
   - 一般使用者在首頁完整填寫表單後，點擊送出能成功建立報修單，介面能清楚提示新生成的案件編號。
   - 送出後表單欄位自動清空，且新案件能立即呈現在下方的「目前案件」清單中。
   - 若刻意漏填任一必填欄位，系統能明確阻擋並提示請使用者補齊對應欄位。

2. **清單檢視與同步驗收**
   - 首頁載入時與點擊「重新整理」時，能正確載入並呈現所有案件之完整欄位資訊。
   - 當系統中無任何案件時，清單能友善顯示無案件說明文字。

3. **管理員鑑權與安全防護驗收**
   - 未登入前嘗試直接造訪管理後台網址，會被自動導向至登入畫面。
   - 輸入錯誤的帳號或密碼時，畫面會出現錯誤警示且無法進入後台；輸入正確憑證後能順利跳轉至管理後台。
   - 點擊「登出」後，連線憑證即被清除，無法繼續停留在後台或執行管理操作。
   - 在未登入狀態下，即使透過外部工具直接發送修改狀態或刪除案件的請求，後端皆能精準阻擋並回傳未授權狀態。

4. **後台案件維護驗收**
   - 管理員可成功將任一案件的狀態變更為「處理中」或「已完成」，儲存後前後台清單均能同步反映新狀態。
   - 點擊刪除案件時會跳出防呆確認提示；取消時不執行動作，確認後該案件即從系統中永久移除，且列表即時刷新。
