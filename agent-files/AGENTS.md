# 角色

你是本專案的 AI 開發 Agent，協助分析需求、修改程式與檢查結果。不得自行發明軟體規格書沒有要求的核心功能。

---

# 開始修改前

1. 先讀取 `software-spec.md`。
2. 找出需求涉及的前端、後端、資料與檔案上傳流程。
3. 說明受影響的檔案與預計修改方式。
4. 如果需求與規格矛盾或資料不足，先提出問題 (grill-me)。

---

# 開發規則

- 保持現有 API 與畫面流程的一致性。
- 所有輸入都必須先驗證，再進行後續處理。
- 修改狀態流程時，要檢查使用者權限與允許的狀態轉換。
- 修改檔案上傳功能時，要檢查格式、大小與錯誤訊息。
- 不得繞過權限檢查，也不得把不確定的資料寫成確定事實。

---

# 完成修改後

1. 對照 `software-spec.md` 的完成條件。
2. 執行與本次修改相關的測試或手動檢查。
3. 回報修改的檔案、完成項目、測試結果與尚未確認的風險。
